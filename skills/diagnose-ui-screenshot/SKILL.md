# 截图 UI 排障

依据截图中的可见证据定位问题，再用代码和运行结果验证原因。不要仅凭截图猜测具体实现。

## 执行流程

1. 看图定位
   - 先检查图片内容，指出异常所在区域、受影响元素和实际表现。
   - 区分可见事实与推测；记录视口方向、裁切边界、文字换行、间距、对齐、层叠和溢出等线索。
   - 图片模糊、关键区域被裁掉或缺少正常状态对照时，明确说明证据限制。

2. 明确预期
   - 从用户描述、设计稿、现有页面惯例或测试中确认预期表现。
   - 缺少必要信息时采用最小且保守的假设，并在结论中标明。

3. 定位实现
   - 搜索截图中文字、组件名、路由或相关样式，读取最相关的组件与 CSS。
   - 检查固定尺寸、flex/grid 约束、定位上下文、`overflow`、`z-index`、字体、图片尺寸和断点规则。
   - 将每个原因假设同时关联到截图证据和具体代码，不把相关性当作根因。

4. 复现与缩小范围
   - 在与截图相符的视口和状态下复现；记录控制台错误、布局尺寸和资源加载状态。
   - 逐项排除内容数据、资源缺失、浏览器差异、响应式断点和样式覆盖问题。

5. 修复
   - 用户要求修改时，实施影响范围最小的修复并保持现有设计规范。
   - 不通过隐藏内容、删除功能或只适配单一截图尺寸来掩盖问题。

6. 视觉验证
   - 在原始截图对应视口重新渲染并比较异常区域。
   - 至少补查一个相邻桌面尺寸和一个移动尺寸，确认无重叠、截断、意外换行或布局跳动。
   - 能运行浏览器截图或视觉测试时优先使用；不能运行时明确报告验证缺口。

## 输出要求

- 按“截图证据、根因、修改、验证、剩余风险”组织结果。
- 引用相关文件与位置；把尚未验证的判断标为假设。
- 若截图与代码不足以确定唯一根因，给出按证据强弱排序的候选原因和下一项检查。
